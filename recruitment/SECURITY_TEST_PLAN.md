# BROOK本部採用管理 セキュリティ検証手順（本番未実施）

## 準備
- 本番へのSQL適用は承認後のみ。現時点では開発ブランチに設計を保存しただけ。
- バックアップを取得し、テスト環境で先に実施する。
- recruitment_admins には、本人確認済みの本部採用担当者だけを登録する。
- 本番データを使わずダミー応募者で検証する。

## 必須テスト
1. 未ログイン：求人管理・応募者・学校連絡先の SELECT/INSERT/UPDATE/DELETE が拒否される
2. 一般職員：既存 organization_members の role=member でも採用情報にアクセスできない
3. AI記録管理者：organization_members の role=admin でも採用権限がなければ拒否
4. 本部採用担当者：recruitment_admins に有効登録されている場合のみ一覧を閲覧できる
5. 採用担当者を is_active=false に変更：再取得時にアクセスが拒否される
6. 採用担当者が自分自身を追加・復活・更新できない
7. 匿名応募：直接 recruitment_applicants に INSERT できない
8. 管理画面：応募者の悪意あるHTMLが文字列として表示される
9. スマホ：ログイン・ログアウト・事業所絞り込み・表示の崩れを確認
10. 事業所の異動・応募求人の変更時に関連情報の整合性を確認
