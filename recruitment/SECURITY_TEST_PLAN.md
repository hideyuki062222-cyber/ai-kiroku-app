# 検証記録と公開前の残作業（2026-10-29）

## 実施済み
- PGlite隔離DB: 採用SQLを実際に実行。RLS・GRANT・未公開・上書き条件・受付・二重送信・権限取消・競合・削除・監査と、既存の番兵データ／ポリシーの不変性を検証（25チェック）。
- 同じローカル採用テストDBをバイナリ書き出し→別インスタンスに復元し、応募データを比較。
- Fetch受付ハンドラ: 出自、本文サイズ、型、連絡先、同意、CAPTCHA hostname/action、停止状態、DB障害、レート制限、CORS（14チェック）。外部送信はすべてモック。
- UI: 3勤務地、共通条件、個別上書き、確認応募→本部表示、状況更新、XSS、ログアウト、ネットワーク不使用、個人情報のブラウザ永続保存なし（11チェック）。
- REST接続層: ログイン拒否・成功、期限切れ・権限喪失、通信失敗、0件更新を成功扱いしない、受付の保存確認（api.cjs）。
- ブラウザ: PCで求人詳細→架空応募→本部詳細を実操作。390px幅のiframeでスマホ相当表示を確認（iPhone実機ではない）。
- 既存出勤簿: 一般職員・管理者の保存、復元、スタッフ/年月切替、通信失敗、競合、Excel出力、印刷DOM、移行を既存テストで検証。
- 既存食事管理: 保存・欠食・集計・競合・表示を既存テストで検証。
- AI記録: 記録一覧・記録への直接移動、エスケープ、権限外表示を既存テストで検証。
- 共通HTML構文・ナビゲーション検証。Pythonの既存安全テスト17関数を直接実行（pytestはこの環境にない）。
