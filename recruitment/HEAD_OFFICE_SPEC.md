# BROOK本部一括採用管理 仕様確定（2026-10-29）

## 決定事項
- 株式会社BROOK本部で採用業務を一括管理する。
- 居宅介護KIZUNA、COZY、堺新事業所（開設予定）の求人・応募を同じ管理画面で扱う。
- 事業所で絞り込み可能にするが、採用担当者の権限は本部単位で管理する。
- AI記録の organization_members.role='admin' を採用担当者の権限として流用しない。
- 採用担当者だけが応募者の氏名・連絡先・選考履歴を閲覧できる。
- 学校・専門学校・大学への求人送付と返信状況を一括管理する。

## データモデル案（未適用）
- recruitment_departments: 募集先（KIZUNA、COZY、堺新事業所など）
- recruitment_admins: 採用担当者 user_id（auth.users と連携）、有効/無効、権限
- recruitment_jobs: 求人票（募集先、雇用形態、公開状態）
- recruitment_applicants: 応募者（個人情報、応募先、進捗）
- recruitment_school_contacts: 学校窓口と送付・返信状況
- recruitment_activity_log: 採用操作履歴

## セキュリティ方針
- 応募者情報へのアクセスは recruitment_admins による本部採用権限を必須とする。
- 既存の AI記録の事業所管理者権限は採用情報閲覧権限としない。
- 公開応募フォームは匿名の直接テーブル書き込みを許可しない。入力検証・レート制限のある受付エンドポイント経由。
- SQLは RLS・GRANT・外部キー整合性・個人情報の保存期間を確認後に作成する。
- GitHub の公開リポジトリに応募者データ、秘密鍵、履歴書を保存しない。
- 本番DBに反映する前にバックアップ、テスト、明示的な承認を得る。

## 旧ドラフトへの注意
database/recruitment_draft.sql は組織別管理を仮定した初期案であり、**本部一括管理には適用しない**。本部専用権限の設計に置き換えるまで実行禁止。
