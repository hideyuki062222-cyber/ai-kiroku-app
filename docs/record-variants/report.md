# 確認済みの事実を保つ文章表現の改善

旧版の調査対象は固定HTML a8fa212e05b08867c5a426d13f05baa8847e4165。現行の比較元はPR #29公開版 c0436637eb7f50d8c517ca7abda35aa32afc2be0です。

## 原因と旧版との違い

PR #29では確認済みの事実を固定の表現へ変換していたため、同じ入力なら同じ文章でした。旧版の nextVariantSeed は入力署名をハッシュ化した回数を端末へ記録し、cloudNextVariantSeed は next_variant_seed RPCで共有回数を取得します。variantDigits は回数を20進の4桁に分解し、訪問文・支援文にそれぞれ接頭句・対象・動詞・結びを付加します。組み合わせ上限は160,000通りです。

旧追加文ルーチン単体では、訪問文・支援文とも5,000回で5,000種類（重複0）を再現しました。ただし、実際に運用された完全な記録で5,000回重複しなかったという報告自体は未検証です。例えば次の旧追加文は、未入力の観察・対応を含み得ます。

> あわせて、表情や受け答えの様子を確認し、普段との違いがないか見守った。

> 支援中は、本人の表情や反応を確認しながら、本人のペースに合わせて対応した。

## 実装

回数を複数の選択桁に分ける方式を取り入れ、確認済みの定型節だけに、見られた／見受けられた、介助した／介助を行った、確認した／確かめた等の同義表現と、文の接続・分割を適用します。語順は前後関係や行為者を変えない範囲に限定し、自立部分・職員の介助・支援後の状態の順序を維持します。自由記載・発言・プロフィールを書き換えず、追加の観察や支援を挿入しません。

生成後、既存の同一施設・同一利用者の閲覧可能な直近300件を使い、最大32候補を比較して完全一致と高類似を減らせる表現を選びます。同じログイン職員・施設・利用者の直前の生成文も参考にします。安全な代替が尽きれば似た文章を許容し、PR #29の類似表示と通常の1回保存を維持します。比較待ちの間に職員が編集した文章は自動変更しません。

DBカウンターRPCは再利用しません。生成回数は画面内の数値だけで管理し、利用者情報や入力署名を端末へ永続保存しません。再読込すると回数がリセットされ、複数端末の同時生成を一意にする保証はありません。新規保存の既存daily_facts JSONに表現のseedと版を追加し、過去のJSONや記録を変更しません。

「付き添いましました」等は旧polite処理が複数の語尾置換を連続適用していたためでした。語尾と接続の両方を、最初に一致した変換を1度だけ適用する方式に直しました。

## 検証と制限

25ケース×5,000回＝125,000生成を自動検証。15サービス、服薬未確認・拒否、自立部分、発言・補足の不変、異なる事実の保持、必須冒頭、二重活用・不自然な接続、長さの最小／最大値を確認しました。語尾・接続を正規化して元の表現と照合する検証であり、介護職による全文章の第三者評価は未実施です。各ケースの長さと例はresults.jsonに記録しています。

画面の15サービス、選択欄、任意欄、ボタンを追加していません。生成までの通常6操作＋正式保存1操作、入力欄の高さ1518px（390px幅）を既存ブラウザテストで確認します。別表現の候補作成は自動で行い、必須クリックは増えません。

安全な表現数は有限です。最小入力で5,000種類を作ることはできず、重複は残ります。重複回避のための事実追加・ランダムな水増しはしません。全端末・過去全期間での重複ゼロや、文字類似度と意味の同一性の一致は保証しません。

保存済み記録・プロフィール・RLS・権限・担当割当・各出力を変更しません。追加料金のあるAPI、サービス、DB変更は不要です。本番マージ・公開は未実施です。Windows/iPhone実機と本番DBへの保存は未検証です。
