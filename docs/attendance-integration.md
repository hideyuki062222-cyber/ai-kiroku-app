# KIZUNA出勤簿の統合・移行

## 運用

- 共通メニュー：今日｜担当割当｜申し送り｜AI記録｜出勤簿｜出納帳。
- 既存のAI記録アカウントでログイン。本人判定は organization_staff.linked_user_id と認証ユーザーIDの一致。氏名・入力されたメール・URLの職員IDでは判定しない。
- 職員管理は管理者専用。ログイン利用者とログインなし職員を同じマスターで表示。ログインなし職員は管理者が代理入力。本人による操作には本人専用アカウントと管理者による紐付けが必要。共用ログインを本人確認として使わない。
- 未登録のログイン利用者は職員管理の「新しいログイン利用者を職員に追加」で追加できる。既存のログインなし職員と同一人物なら追加前に本人紐付けを確認する。氏名だけで自動統合しない。
- 入力後は「変更を保存」。通信失敗時は未保存と表示し、入力を残す。別端末で更新された場合は上書きを拒否する。Excelに退避後、再読み込みして調整する。
- 管理者は表示月の全職員、一般スタッフは自分の1シートのみExcel出力。印刷ボタンは表示中の職員を印刷。元のExcelの印刷範囲・数式・罫線・黄色区分を継承。
- 今日画面の勤務は入力済み出勤簿を表示。管理者の未入力一覧は稼働中の全職員が対象。出勤予定者だけを意味しない。

## 既存入力の段階的移行

旧版はブラウザのIndexedDB保存で、サーバーから取得できない。旧版と元のHTMLは変更しない。

1. 実際に入力した端末・ブラウザで旧KIZUNA出勤簿を開く。
2. 全職員を対象年月に切り替え、Excelを保存する。複数月の場合は月ごとに保存。旧版が職員ごとに年月を保持していることに注意。
3. 統合版へ管理者でログインし、取り込み先事業所を確認する。
4. 保存済みExcelを選択。取り込む各シートについて職員IDと本人を確認し対応付ける。未選択シートは取り込まない。
5. 取り込み前バックアップJSONを保存。既存月を置換する場合は確認が出る。
6. 保存・再読み込み・Excel出力を確認してから通常利用へ移る。途中で通信が失敗した場合は保存済み件数が表示され、残りの対象を再確認する。
7. 元のExcel・バックアップJSON・旧版の端末データは確認が完了するまで保管する。

## 保護と復旧

- ソース退避：backup/pre-attendance-20261019（11052b8cbc0d324f5dddad4442b8c6b50ca8d29d）。
- データベース変更前の職員・メンバー・権限を attendance_backup スキーマに複製。クライアントからはアクセス不可。
- 出勤簿の保存前後を同スキーマの month_revisions に保持。管理用接続で復旧対象を特定して復元する。クライアントへ監査全件を配布しない。
- 不具合時は出勤簿導線を旧版へ戻して利用を停止する。新しい attendance_months と監査履歴は削除しない。復旧前に最新入力を退避する。
- 職員停止・所属削除で本人アクセスを停止。所属削除は職員履歴を残してログイン紐付けのみ解除する。
- 移行SQLは一度だけ適用。既存テーブル・勤務データの削除や上書きは含まない。

## 検証の範囲

- 実DB上のトランザクション内で、管理者・本人・他人・未所属・未認証・職員停止・所属解除・本人紐付け改ざん・更新競合・監査保存を検証し、テスト変更は全てROLLBACK。
- 実際のHTML/JSをJSDOMで実行し、スタッフ別表示、編集・保存・再読み込み、スタッフ/月切替、通信失敗、競合、Excel取り込み、移行前バックアップ、Excel出力、印刷DOMを検証。
- APIはDOMテストではテストダブル。実ユーザーのログインを使ったブラウザE2E・スマートフォンでの視覚/タップ確認は未実施。
- 生成したxlsxをopenpyxlで開き、出力シート数、時刻、数式、黄色区分、元の印刷範囲を照合。
- 本人の端末内の入力済みデータは未取得。実データ移行はExcel提供または管理者の取り込み操作後に完了となる。

DOMテスト: `JSDOM_PATH=/path/to/jsdom node tests/attendance_dom.cjs` (jsdom 26.1.0)
DBテスト: setup SQLと tests/attendance_rls.sql を同一トランザクションで実行してROLLBACK。未導入の検証環境または初回適用前に使用。
