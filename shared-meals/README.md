# 食事管理（共有運用版）

既存Supabaseのログイン基盤と容量のみ共用し、施設・職員所属・利用者・食事・請求データは sm_ 接頭辞の専用テーブルに保存します。AI記録のデータを取得・転記しません。

公開先: https://hideyuki062222-cyber.github.io/ai-kiroku-app/shared-meals/

1. 管理者は登録済みのメールアドレスとパスワードでログイン。
2. 「施設・職員管理」で施設名と管理者の表示名を登録。
3. 職員に同じURLを共有し、初回は「職員登録」を行ってもらう。
4. 管理者が本人のメールアドレスを確認し、施設の職員に追加。職員登録のみでは食事情報にアクセスできません。
5. 「利用者・料金設定」で利用者と食事形態、各食の白米量、開始日、通常の食事予定を登録。
6. 月間予定を作成し、毎食の提供済み・欠食をチェック。別端末の更新は「最新に更新」で取得。

朝330円・昼440円・夕550円。欠食・予定は請求しません。月間集計で各食の食数・金額と総額を確認。過去の提供済み食事の単価は保持します。

ログイン基盤は共通のため、同じアカウントのパスワードを変更すると既存アプリにも影響します。所属と操作権限は独立しています。メール認証の既存設定は変更していません。管理者は職員本人に登録アドレスを直接確認してから権限を付けてください。

無料プランを維持します。容量・通信量の枠は既存システムと共用です。追加料金が必要な契約・アップグレードは自動で行いません。

## 設置担当者向け
SQLは01→02の順に初回のみ実行。既存のpublic/privateのテーブルや関数は上書きしません。sm_privateとsm_historyはAPI公開対象にしないでください。初期管理者は確認したAuthユーザーをsm_private.app_ownersに登録します。web/のみ公開。秘密キー・パスワード・実利用者情報をソースに置かないでください。
